# Rule Catalog

Initial rule identifiers are versioned and owned by core:

| ID | Area | Intent |
| --- | --- | --- |
| CR-SETUP-001 | setup | a contributor-facing setup guide exists |
| CR-SETUP-002 | setup | runtime/toolchain prerequisites are stated |
| CR-SETUP-003 | setup | package-manager installation is discoverable |
| CR-SETUP-004 | setup | development setup steps are actionable |
| CR-SETUP-005 | setup | environment configuration is discoverable |
| CR-TEST-001 | testing | a test command is discoverable |
| CR-TEST-002 | testing | reproduction/testing guidance is present |
| CR-TEST-003 | testing | continuous integration is discoverable |
| CR-TEST-004 | testing | test expectations are stated |
| CR-CONTRIB-001 | contribution | contribution workflow is documented |
| CR-CONTRIB-002 | contribution | pull-request workflow is discoverable |
| CR-CONTRIB-003 | contribution | review expectations are discoverable |
| CR-CONTRIB-004 | contribution | support and contact path exists |
| CR-SECURITY-001 | security | vulnerability reporting path is present |
| CR-ISSUE-001 | issue | issue states a concrete problem or goal |
| CR-ISSUE-002 | issue | issue includes reproduction or acceptance evidence |
| CR-ISSUE-003 | issue | issue states expected behavior |
| CR-ISSUE-004 | issue | issue defines technical scope |
| CR-ISSUE-005 | issue | issue includes acceptance criteria |
| CR-ISSUE-006 | issue | issue defines done and validation |

Each rule records purpose, severity, evidence, logic, recommendation, and false-positive considerations.
